# `www/docs` 文件分析報告

本報告針對 `www/docs` 目錄下的所有文件進行分析，旨在提供專案文件結構、模組狀態及關鍵發現的總覽。

## 1. 文件結構總覽

`www/docs` 目錄結構清晰，主要分為以下幾類：

*   **專案管理與規範**（根目錄）：包含 Sprint 規劃、檢查清單、編碼規範、模組依賴分析等。
*   **功能模組文件**（子目錄）：每個主要功能模組（如 `about`, `menu`, `locations` 等）都有獨立的目錄，通常包含：
    *   `plan.md`：功能規劃與需求。
    *   `schema.md`：資料庫結構設計。
    *   `todo.md`：待辦事項與進度追蹤。
    *   其他特定文件（如 `development-notes.md`）。
*   **資料庫定義**（`sql` 目錄）：包含 SQL 腳本。

## 3. 關鍵發現與建議

### 3.1 開發規範與品質
*   **編碼規範**：`gpt-codex-guidelines.md` 明確定義了專案結構（React 後台 + PHP API）、命名規則與開發流程。建議嚴格遵守，特別是「新增功能必須依現有結構建立專屬 Route 與 Action」。
*   **回顧與改進**：`20251114-1656-summary-external-links-retro.md` 記錄了早期開發的錯誤（如路由誤用、React build 遺漏）。這些經驗應應用於後續模組開發，例如：
    *   前端改動後務必執行 build。
    *   API 統一使用 `parseRequestData()` 處理 JSON。
    *   操作記錄統一使用 `logAction()`。

### 3.2 模組依賴性
*   `module-dependency-analysis.md` 提供了詳細的依賴分析。
*   **高優先級**：FAQ、Contact、Franchise（依賴度低，可獨立開發）。
*   **需等待項目**：Menu、News 高度依賴「媒體資源庫」與「標籤系統」。目前媒體資源庫看來已就緒，可以開始進行這些模組。

### 3.3 資料庫設計
*   各模組都有獨立的 `schema.md`，設計規範統一（包含 `created_at`, `updated_at`, `status`, `sort_order` 等標準欄位）。
*   `sql` 目錄下的檔案（如 `cms_tables.sql`）提供了具體的建表語句，部分已包含初始資料。
*   **建議**：在實作新模組時，應先檢查 `schema.md` 是否需要根據最新需求更新，再建立 Migration 檔案。

### 3.4 待辦事項 (Todo)
*   各模組的 `todo.md` 清晰列出了後端、前端、內容與測試的待辦項目。
*   **測試缺口**：多個模組的 Todo 中都提到了測試（單元測試、整合測試），但目前似乎較少看到具體的測試代碼或執行紀錄。建議在後續開發中加強測試覆蓋率。

## 4. 總結

`www/docs` 提供了非常完整且結構化的專案文檔。專案目前處於從基礎建設（Sprint 1）邁向核心業務模組（Sprint 2+）的階段。

**下一步建議：**
1.  **確認 Sprint 優先級**：根據 `sprint-plan.md`，目前應關注 **Sprint 2 (Menu)** 或 **Sprint 3 (Locations)** 的收尾與 **Sprint 4 (Food Safety)** 的啟動。
2.  **補強測試**：針對已完成的模組（Locations, FAQ），建立自動化測試以確保穩定性。
3.  **持續更新文檔**：隨著開發進行，持續更新 `todo.md` 與 `schema.md`，保持文件與程式碼的一致性。
